## Source Anchor

Aoyagi's displayed Case 2 chart chooses the residual-block coordinate
`(J+1,J+1)` as the selected coordinate.  In the local chart this selected
coordinate is renamed `u`, while the other residual-block coordinates carry a
factor of `u`.  The stopped Case 2 terminal display on PDF pp. 21-22 then uses
the terminal block, its diagonal weights, and the remaining right product.

This checkpoint packages only those elementary facts:

- the finite residual-block center ideal becomes generated by the selected
  variable `u` in the displayed source-coordinate chart;
- under actual-width exhaustion `n(S+1)=J+1`, the stopped terminal matrix can
  be written using original source rows `1..J+1`;
- the following product remains a supplied matrix `F`.

## Pen-And-Paper Reproduction

Let

```text
phi(d_(J+1,J+1)) = u,
phi(d_ij) = u * r_ij     for (i,j) != (J+1,J+1)
```

on the finite residual-block center

```text
{(i,j) : J+1 <= i <= M(S), J+1 <= j <= M^(S+1)}.
```

Since the selected coordinate itself belongs to the center, `u` is one of the
transformed center values.  Every transformed center value is divisible by
`u`, and the transformed center ideal is exactly `(u)`.

The existing displayed source-chart terminal calculation gives, for any
supplied following matrix `F`,

```text
ideal((blockdiag(oldTopWeight, transformed residual block)
        * [old source rows ; source following factor]) * F)
  =
ideal((terminalWeight(post.stageRelabelSuccZero)
        * originalRows(1..J+1)) * F),
```

provided the actual next width is exhausted:

```text
n(S+1) = J+1.
```

The same actual-width side condition also relabels the post-state exponent and
level data from old `(S,J+1)` to `(S+1,0)`.

Combining these statements is a useful boundary package: the selected source
chart principalizes the finite residual-block center ideal and the stopped
terminal product has the actual-width original-row form.
