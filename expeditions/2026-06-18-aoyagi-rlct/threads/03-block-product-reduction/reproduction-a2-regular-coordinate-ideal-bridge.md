# Reproduction - A2 regular-coordinate ideal bridge

Date: 2026-06-24.

Status: reproduced before Lean implementation.

## Source Anchor

Aoyagi PDF p. 13 treats entries of the three blocks

```text
C1 - Er,   F2,   F3
```

as the regular variables.  The scalar coordinate index already formalises these
three entry families as

```text
(ι x ι) ⊔ (ι x ν) ⊔ (μ x ι).
```

## Calculation

Let

```text
value X F2 F3 : AoyagiRegularBlockCoordinateIndex ι μ ν -> R
```

send a scalar coordinate to the corresponding entry of `X`, `F2`, or `F3`.
The ideal generated by these scalar coordinate values is

```text
< value X F2 F3 c | c in AoyagiRegularBlockCoordinateIndex ι μ ν >.
```

Unfolding the disjoint union gives exactly

```text
< entries X > + < entries F2 > + < entries F3 >.
```

This is the regular block-entry ideal

```text
regularBlockEntryIdeal X F2 F3.
```

The equality is algebraic and remains true for arbitrary index types.  The
finite Aoyagi application comes from the surrounding coordinate-count theorems,
not from this ideal equality.

The two inclusions are direct:

- each scalar coordinate is an entry of one of `X`, `F2`, or `F3`;
- each entry of `X`, `F2`, or `F3` is the value of the corresponding tagged
  coordinate.

Combining this with the regular/residual ideal split gives the canonical
source-rank package:

```text
matrixEntryIdeal(productDifference)
  = entryIdeal(S.Ctop - 1, -S.B, lowerLeftBlock S.L) + <entries S.D>.
```

## Nonclaims

- No residual `D` coordinate is included.
- No analytic regular-coordinate chart is constructed.
- No analytic ideal/germ transport, chart coverage, Jacobian compatibility,
