**Answers**
1. `collectAxioms − FOUNDATIONAL − @[cited]` is sound and complete for the specific predicate “no non-allowlisted axiom constants occur in the checked transitive dependency graph of `D`”. Lean documents that axiom dependencies are tracked automatically and that `#print axioms` reports them directly or indirectly, including through imported proofs. It is **not** a complete audit of the whole trusted computing base; `unsafe`, `@[implemented_by]`, `@[extern]`, plugins, and initializer code are outside this predicate. ([lean-lang.org](https://lean-lang.org/doc/reference/latest/Axioms/))

2. The forget-proofness argument is correct. Removing `@[cited]` cannot hide an axiom dependency; it only moves that axiom from “accounted” to `UNACCOUNTED`. Tagging a wrapper theorem does not help, because `collectAxioms` reports the underlying axiom names, not theorems that mention them. ([lean-lang.org](https://lean-lang.org/doc/reference/latest/Axioms/))

3. Parametric attribute is the stronger design. In `v4.29.0`, `registerParametricAttribute` is a persistent env extension, global-only, and by default exports only public declarations, so using it keeps the audit data semantic and machine-readable rather than comment-parsed. The exe pattern in [CitedAudit.lean](/home/ubuntu/workspace/geometry-of-dln-fibre/.claude/worktrees/rlct/lean/scripts/CitedAudit.lean:76) is the right one: [Attributes.lean](/home/ubuntu/.elan/toolchains/leanprover--lean4---v4.29.0/src/lean/Lean/Attributes.lean:248), [Environment.lean](/home/ubuntu/.elan/toolchains/leanprover--lean4---v4.29.0/src/lean/Lean/Environment.lean:2318), [ImportingFlag.lean](/home/ubuntu/.elan/toolchains/leanprover--lean4---v4.29.0/src/lean/Lean/ImportingFlag.lean:18). I would keep cited axioms public and reject `@[cited]` on non-axioms.

4. Keep the allowlist static at 3. Lean’s standard set is 7, but the other 4 are exactly the things you want to go red: `sorryAx`, `Lean.trustCompiler`, `Lean.ofReduceBool`, `Lean.ofReduceNat`. `sorry` should stay unaccounted. `native_decide` should also stay unaccounted, but at this pin it is caught via a generated bespoke axiom, not `Lean.ofReduceBool`. Double coverage with `scripts/sorries` is good. ([lean-lang.org](https://lean-lang.org/doc/reference/latest/Axioms/))

5. For the location invariant, module identity is cleaner than filesystem globbing inside Lean. `Environment` naturally gives you module provenance, not source paths. I would enforce either “last module component is exactly `Cited`” or an explicit module allowlist; the current suffix test is too weak. Also add: every decl carrying `@[cited]` must itself be an `axiom`.

6. Clean-build false-green disagreement between `#audit_cited` and the gate looks unlikely if cited axioms are public and the exe keeps `loadExts := true`. Real mismatch modes are: unsaved buffer vs stale oleans, elaboration-error/fallback environments, or importing without extensions/wrong visibility level, all of which tend to produce false red, not false green.

7. The slogan that is defensible is: **green = no unaccounted axioms in the imported gate environment**. What it does **not** mean is “small-kernel only” or “bibliographically legitimate cites”. If you want the stronger slogan, add explicit gates for `unsafe`, `@[implemented_by]`, and `@[extern]`, and keep human review over the cited source strings; the machine can enforce accounting, not honesty.

If you harden only three things, I would do:
1. Fix the `native_decide` rationale/docs.
2. Tighten `isInCitedFile` to exact `Cited` or an allowlist.
3. Add “`@[cited]` implies `axiom`” plus an explicit no-`unsafe`/no-`implemented_by`/no-`extern` gate.
