**1. DEGENERATION (L6)**
Yes: the clean independent route is explicit type-A barcode degeneration, not general orbit-closure theory. Use normal forms and prove the multisegment move
`M[a,d] ⊕ M[c,b] ⇝ M[a,b] ⊕ M[c,d]` for `a < c ≤ b+1 ≤ d` (`M[c,b]=0` when `c=b+1`), then close under direct sums. Standard fact: these box moves generate the rank-order degeneration preorder for equioriented type A.

Lean bottleneck: avoid `TopologicalSpace.closure`. Mathlib’s point-space Zariski topology is minimal; use ideal closure:
`MvPolynomial.zeroLocus k (MvPolynomial.vanishingIdeal k S)`.
Core API: `MvPolynomial.vanishingIdeal`, `MvPolynomial.mem_vanishingIdeal_iff`, `MvPolynomial.zeroLocus`, `MvPolynomial.mem_zeroLocus_iff`, `MvPolynomial.aeval`. The one-parameter limit lemma is bounded: if `F : k → Rep` is polynomial, `F t ∈ O_M` for `t ≠ 0`, and `F 0 = B`, then every polynomial vanishing on `O_M` vanishes at `B`; reduce to a univariate polynomial zero on infinitely many `t`. The multi-module part is the combinatorial “rank order generated by box moves”.

**2. SMOOTH ORBIT + TANGENT = im δ**
The group side is easy: coordinate ring of `G_d` is a localization of a polynomial ring at the product of determinants. Use `Algebra.FormallySmooth.mvPolynomial`, `Algebra.FormallySmooth.of_isLocalization`, `Algebra.Smooth.of_isLocalization_Away`, `Algebra.FormallySmooth.of_equiv`, and `Algebra.IsSmoothAt k m` (`Smooth/Locus.lean`).

The orbit side is not automatic. Without group schemes/quotients, a theorem “transitive smooth group action gives smooth orbit” is not available at low friction. Ring-side homogeneity via `Algebra.smoothLocus`, `Algebra.isOpen_smoothLocus`, dense smooth locus, and action-stability would force a Spec/scheme-style detour or a sizeable reproof. Minimal friction is an explicit normal-form/pivot chart around `M`: identify a principal-open neighbourhood of the orbit/rank locus with `Localization.Away f (MvPolynomial (Fin r) k)`, where `r = finrank k (LinearMap.range δ⁰)`. Then `IsSmoothAt` is immediate by localization + algebra equivalence.

**3. TANGENT IDENTIFICATION (L2)**
Mathlib has the raw cotangent API, not a finished affine-Jacobian tangent theorem. Use `Ideal.Cotangent`, `Ideal.toCotangent`, `Ideal.Cotangent.lift`, `Ideal.cotangentToQuotientSquare`, `CotangentSpace`, `ResidueField`, and `dual_finrank_eq`. For derivatives use `MvPolynomial.pderiv`, `pderiv_X`, `pderiv_X_self`, `pderiv_X_of_ne`, `pderiv_mul`, `pderiv_pow`, `pderiv_map`.

So “`m/m²` dual = Jacobian kernel” is a local sub-library. Identifying that kernel with `LinearMap.range δ⁰` is clean only if obtained from the orbit chart/differential. If done from determinantal generators, it becomes a real tangent-to-rank-locus project: differentiating minors of interval products and proving the resulting equations cut out exactly `range δ⁰`.

**4. RANKING**
Hardest: `L6` and Jacobian-style `L2`. `L6` is hard for the combinatorial generation theorem, not for the polynomial limit lemma. `L2` is hard if you go through minors.

`L1` is comparatively bounded: prove the orbit is polynomial image of irreducible `G_d`; use target coordinate ring domain/localization and `RingHom.ker_isPrime`, plus a Nullstellensatz/density lemma for principal opens. `L3` is bounded after an explicit chart, but hard via abstract homogeneity.

**5. ALTERNATIVE**
Cleanest bypass: build a normal-form pivot chart for the dense orbit inside `Z_M`. This can package `L2+L3` together and compute
`varietyDim Z_M = finrank k (LinearMap.range δ⁰)` directly from an open affine chart, with smoothness and tangent dimension as byproducts.

I would not choose direct determinantal-variety dimension: quiver determinantal prime/height/CM theory is larger than the orbit chart. Stabilizer dimension is tempting, but still needs quotient/fiber-dimension machinery absent from Mathlib’s ring-side API.
