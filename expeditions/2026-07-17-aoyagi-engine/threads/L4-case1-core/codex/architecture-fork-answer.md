## 2. What the ideal route may fail to provide

### (a) From ideal identity to the local RLCT

**FACT:** Provided both ideals live in the same local analytic ring, the conclusion is a direct composition:

\[
\langle f_i\rangle=\langle b_i\rangle
\overset{A}{\Longrightarrow}
\operatorname{rlctAt}\!\left(\sum f_i^2\right)
=
\operatorname{rlctAt}\!\left(\sum b_i^2\right)
\overset{C}{=}\frac12\min
\overset{D}{=}\frac{cCodim}{2}.
\]

No coordinate atlas, residual-support invariant, `couplingClear`, or phantom-branch argument is logically needed here.

A separate local-to-global lemma may still be required to pass from `rlctAt` to `rlctGlobal`. Nothing supplied shows that this global assembly itself needs `FoldStepInvAt`.

### (b) Making the \(b_i\) monomial

This is the important caveat.

- If the exceptional coordinates are an invertible analytic coordinate change, the ideal identity remains in the same germ and the direct composition above is valid.
- If they come from a genuine, non-invertible blow-up \(\pi\), the correct statement is generally
  \[
  \pi^*\langle f_i\rangle=\langle b_i\rangle,
  \]
  not an equality of ideals in the original local ring. Object A alone cannot compare ideals in different rings. One must also account for chart coverage and the Jacobian/discrepancy of \(\pi\).

Even in the second case, monomialisation can be handled at the **ideal level**: prove that the extended/pulled-back entry ideal is the monomial ideal on each terminal chart. This does not require substituting every residual coordinate at every matrix-clearing step or maintaining degree-one support.

Thus some chart geometry may be unavoidable; the current support-tracking encoding is not thereby necessary.

### (c) Obtaining \(cCodim\)

**FACT:** If Object C concludes the monomial ideal’s RLCT directly and Object D identifies its Newton minimum with `cCodim`, then no `Resolution` object is mathematically required.

If the existing engine only exposes `2 · rlctAt = cCodim` through a `Resolution` argument, that may merely be an API packaging choice. It is genuinely necessary only if that object carries missing mathematical data such as:

- the blow-up Jacobian,
- completeness of the chart cover, or
- the local-to-global minimum.

## 3. Decisive cheapest check

Create an isolated Lean smoke theorem importing A, C, D, and the local-to-global bridge—but no coordinate-resolution modules:

```lean
idealRouteSmoke
  (hIdeal : entryIdeal (∏ C) = monomialIdeal b)
  (hChain : MonomialDivisibilityChain b)
  (hCodim : newtonMin b = cCodim) :
  rlctGlobal loss = cCodim / 2
```

Attempt to prove it solely by A → C → D.

The decisive outcome is the type/domain check:

- If it elaborates, the coordinate resolution is not needed for the payoff.
- If `entryIdeal (∏ C)` and `monomialIdeal b` necessarily inhabit different rings after blow-up, then a chart/Jacobian interface is genuinely missing.
- If failure occurs only because C is packaged behind `Resolution`, that shows an API dependency, not mathematical necessity.

## 4. Ideal-route re-architecture

1. Define the ideal generated by matrix entries.
2. Prove a generic lemma that invertible left/right matrix multiplication preserves that ideal.
3. Formalise the Schur-clearing steps using \(Q,P\), with the cross-term discharged by ideal closure under multiplication.
4. Fold these equalities to obtain the terminal diagonal ideal.
5. At the coordinate boundary only, prove either:
   - same-ring equality with a monomial ideal, or
   - chartwise pullback equality plus the required Jacobian/coverage theorem.
6. Apply A, C, D, then the local-to-global bridge.

The single biggest risk is that the claimed terminal equality is really only a **pullback equality under a genuine blow-up**. In that case an atlas cannot disappear completely—but it can remain a small boundary component rather than governing every Schur step through coordinate substitutions and support invariants.
