**Q1.** Refute as an unconditional `∀M` statement. The dead leaf is sound when some **interior** residual block `Rmat s * A s`, with `0 < s ∧ s < L`, has nonempty `E` and lift `W` dimensions, because `Hmat_s = B_s * Hmat_{s+1} + (Rmat_s*A_s)*suffix(s+1)` can be nonzero even with `Hmat_L = Rfin = 0`. It fails for `L = 1`: only the identity boundary and dead terminal leaf remain, so `Hmat_0 = 0` and `VvalGen ≡ 0`. It can also fail for degenerate widths, e.g. `M 0 = 0`, `M L = 0`, or all usable interior `r_s := Text s - Text(s+1)` / `c_s := Wext s - Text(s+1)` blocks are empty. It also fails if all positive codimension sits in the terminal Schur slot feeding `Rfin`, since `Rfin := 0` kills that contribution. The `(2,2,2)` dead-leaf computation is evidence for that case, not a uniform theorem without an interior-nonempty hypothesis. **Known:** local definitions; **Inference:** the stated failure classification.

**Q2.** Ranking: **(ii) > (i) > (iii)**. Cleanest is (ii): define `PolySuffix`/`PolyHmat` by the same `suffixAux`/`HmatAux` recursion over `MvPolynomial (Fin N) ℝ`, then prove one recursion-level `eval` naturality lemma. Option (i) is morally the same but worse if phrased as “lift the whole chain,” because `chainOfMt`, `Cgen`, `Agen`, `dite`, and reindex casts all become the main proof burden. Option (iii) is not a good Lean route: the repo’s banked route is explicitly `MvPolynomial.ae_eval_ne_zero`, and I would not assume a v4.29 real-analytic zero-set-nullity lemma that avoids naming a polynomial. Even if such a lemma existed, proving this decoder map analytic through the dependent matrix recursion would likely cost about as much as the polynomial recursion. **Known:** repo uses `MvPolynomial.ae_eval_ne_zero`; **Inference:** no lighter analytic API route should be planned around.

**Q3.** No, a uniform two-coordinate monomial entry does **not** generalize cleanly. The shallow `(2,2,2)` pattern works because the useful block is effectively `s = L-1 = 1`, `suffix L = 1`, `B0 = 1`, and the residual column width is `1`, giving an entry like
```lean
Hmat0 i0 j0 = readE slot row col * readW slot col j0
```
up to the local `rmatPad`/`chainA` casts. In general, the deepest usable interior block `s = L-1` still has to propagate to `Hmat_0` through `B_1 * ... * B_{L-2}`, and if the residual column width is larger than `1`, the local entry is already a sum `∑ a, E row a * W a j`. A witness can isolate one term by setting one `E` coordinate, one `W` coordinate, and one upstream `K/B` path to `1` with all competing slots `0`, but that proves nonzero evaluation of a scalar polynomial; it does not make the entry definitionally equal to `X e * X w` for all `x`.

Recommended path: prove the extra hypothesis “there exists a nonempty usable interior residual block,” then define a **single scalar `PolyHentry`** by the `Hmat` recursion and use `VvalGen ≥ (Hentry)^2` plus `ae_eval_ne_zero`. If that scalar route becomes cast-heavy, fall back to (ii) and define the full `PolyHmat`/`UPolyGen`. Biggest dependent-width risk: choosing and transporting the witness indices through `frameSplitEquiv`, `rmatPad`, `chainA`, `suffix`, and the `HrGen` reindex without losing definitional simplification.
